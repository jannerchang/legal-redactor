# 完整保留全文 LLM 识别架构

全文 LLM 是一条完整的案件级识别路径，不是可被逐项拆散的提示词优化：`RedactionPipeline` 按固定降级链编排双轮全文登记，`LegalEntityAuditor` 负责有界生成和首轮优先合并，`entity_registry` 负责不信任模型的解析、原文校验、冲突与约束物化，`CandidateCollector` 仍是规则/HanLP 候选的唯一发现入口，`LinearRuleEngine` 只验收候选并扩展确定性映射，最终只由 `apply_mappings` 按长词优先替换。未来重构必须完整保留这条路径及下列不变量；不得把全文识别退化为普通候选审计、让模型直接产出替换结果，或绕过现有发现、验收和确定性替换模块。

## Invariants

- 默认全文识别先执行首轮案件级实体登记，再重新阅读全文执行独立补漏；补漏失败或合并失败时保留首轮有效结果。
- 首轮禁用、输入超过上限、传输失败、超时、无效输出或重试耗尽时，必须按固定链路回退逐句窗口并保留可见原因；不得静默截断全文。
- 全文初次登记、JSON 修复和二次补漏共同使用有界单行 JSON 协议：提示词禁止换行和 Markdown，请求发送 `stop="\n"`，只对确属截断的 JSON 做不虚构实体文本的结构闭合。
- 模型只登记原文实体名称和明确的同一主体关系。实体文本必须逐字存在于原文；模型提供的 span、offset、规范化文本或替换值一律不可信，所有位置由本地代码重新精确定位。
- `uncertain`、重复主张及类型、分组、合并、拆分冲突只进入人工复核，不得自动脱敏；`do_not_merge` 必须穿透候选、映射与后处理，禁止把明确不同的主体合并为同一替换值。
- 全文 LLM 只拥有案件级人名与机构语义身份。身份证号、电话、银行账号、案号等结构化标识始终走确定性规则；通过 gate 的行政区划仍由数据库/规则路径保持权威，不能因模型遗漏而删除。
- `CandidateCollector.collect(context)` 是规则、行政区划和 HanLP 候选的唯一发现入口；全文审计可读取这些候选作对照，但不得新增第二套规则发现实现。
- `LinearRuleEngine.discover(...)` 只验收已排序候选并扩展确定性映射，必须接收登记约束；它不得承担模型调用、全文登记解析或最终文本改写。
- `RedactionPipeline.redact` / `redact_many` 继续拥有编排、降级、统计、警告和公开结果形状；`apply_mappings` 继续是唯一最终替换路径，并保持长词优先、重叠保护和机构简称边界规则。
- ModelManager 接口只传逻辑模型 ID；应用、页面、日志、评测报告和发布说明不得泄露本地权重路径。运行时不得从样本库向全文提示词注入案件原文或 few-shot 内容。
- 任何改变上述路径、模块责任、生成终止机制或冲突策略的重构，都必须先补齐覆盖相应不变量的自动化测试，并用真实长文验证完整 JSON 能及时返回、不会中途截断且不会绕过确定性替换。
